# IDEA-016: Interrupted PowerShell tab completion leaves certinext silently doing nothing

- **Status:** Proposed
- **Created:** 2026-11-16
- **Updated:** 2026-11-16
- **Issue:** #41

## Context

On 2026-11-16, in one Windows Terminal PowerShell session, every `certinext`
invocation (including `uvx certinext --version` and `--help`, even piped
through `Out-String`) printed nothing and exited 0. A new terminal worked, and
another typer tool (tdx-tools) worked in the same terminal. It happened again
later in the session after editing an `issue-cert` command line with the arrow
keys.

Cause, reproduced: the session still had `_CERTINEXT_COMPLETE` (and
`_TYPER_COMPLETE_ARGS`) set. With that variable present, typer/click treats any
run as a shell-completion request, answers it, and exits without parsing
`--version`/`--help`. When the recorded completion context has nothing to offer
(for example `_TYPER_COMPLETE_ARGS='certinext --profile '`), the answer is empty
and the exit code is 0:

```powershell
$env:_CERTINEXT_COMPLETE = 'complete_powershell'
$env:_TYPER_COMPLETE_ARGS = 'certinext --profile '
uvx certinext --version     # prints nothing, exit 0
```

The installed completer (from `certinext --show-completion powershell`,
generated by typer) sets these variables process-wide in its scriptblock, runs
`certinext`, then clears them on the last lines, with no `try/finally`. If the
completion is interrupted before those lines run, the variables stay set for
the rest of the terminal session. tdx-tools is unaffected because its trigger
variable is named after its own program (`_TDX_TOOLS_COMPLETE`).

Workaround (confirmed by the user):

```powershell
Remove-Item Env:_CERTINEXT_COMPLETE, Env:_TYPER_COMPLETE_ARGS, Env:_TYPER_COMPLETE_WORD_TO_COMPLETE -ErrorAction SilentlyContinue
```

## The idea

Make the leaked state either impossible or obvious. Candidates, none evaluated
yet:

- Ship or document a PowerShell completer that clears the variables in a
  `finally` block, instead of the typer-generated one.
- Detect the condition: if a completion variable is set but stdin/stdout look
  like an interactive run (a real `--version`/`--help` request), warn on stderr
  instead of answering silently.
- Report the missing `try/finally` upstream to typer.
- At minimum, document the symptom and the `Remove-Item` workaround in the
  README troubleshooting section.

## Why not now

Deferred on 2026-11-16 to focus on the emSign replacement-report breakage
(the vendor removed emSign products from the production catalog). The
workaround is one command, and only interactive PowerShell users who
installed shell completion are affected.

## Open questions & caveats

- Exactly which interruption leaves the variables behind (Ctrl+C during a slow
  completion, a keypress cancelling PSReadLine's menu completion, an exception
  inside the completer) was not determined. The arrow-key editing alone cannot
  set them; only the Tab completer does.
- Whether typer has already fixed this upstream was not checked.
- Detection must not break legitimate completion runs, which also have the
  variable set.
